# 🔧 **Концепция MVP1: "Семейный менеджер дел" + геймификация**

> **Важно**: Этот документ описывает только функционал, который будет реализован в MVP1. Расширенные фичи перенесены в MVP2.

> **Статус**: Ниже описано целевое поведение MVP1, но формулировки обновлены с учётом того, что **уже реализовано в коде** (текущая терминология: *споты*, *задачи* (в UI иногда называются «миссиями»), `TaskTemplate`/`TaskInstance`, Telegram-conversation state).

## **1. Основная идея**

Это не просто список задач. Это:

* **семейный игровой помощник**,
* **домашний питомец/аватар**, который «живет» благодаря выполнению дел,
* **мотивационный инструмент**, который убирает споры «кто должен».

---

## **2. Ключевые сущности MVP1**

### ✓ **Семья / группа**

* Общее пространство семьи.
* Роли участников: **Админ**, **Взрослый**, **Ребёнок**.
  * **Админ** — создаёт семью, управляет участниками (приглашает и удаляет), настраивает семью (лидерборд, уведомления и т.п.), может менять роли других участников.
  * **Взрослый** — может просматривать и выполнять задачи (в игровом UI могут называться «миссиями»), видеть статистику семьи и спотов, отправлять похвалу (когда появится).
  * **Ребёнок** — может просматривать и выполнять задачи (миссии) и видеть своё количество очков.
* В семье может быть несколько админов.
* Все участники используют один и тот же Telegram-аккаунт для участия в разных семьях и могут переключаться между семьями в разделе «Семья».
* Все задачи и очки существуют в контексте конкретной семьи (нет общих «глобальных» очков между семьями).
* Один человек может участвовать в нескольких семьях (например, своя семья и семья бабушки/дедушки).
* Приглашения по специальной ссылке, которую админ отправляет в мессенджере.

### ✓ **Споты (в т.ч. питомцы)**

* В семье может быть несколько спотов.
* Спот — это "объект заботы" или область ответственности. В коде поддерживаются типы:
  * питомцы (кот/собака/хомяк/и т.д.),
  * комнаты/зоны (кухня/ванная/детская/и т.д.),
  * предметы/устройства (стиральная машина/холодильник/и т.д.),
  * прочее.
* Спот может быть **персональным** — привязанным к конкретному члену семьи (например, "Саморазвитие: Вася" или "Здоровье: мама").
  * В такой спот добавляются задачи/миссии саморазвития.
  * Выполнение этих задач также приносит звёздочки (очки) и влияет на статистику семьи.
* У каждого спота есть **настроение** (`MoodScore` 0–100), которое зависит только от задач этого спота.
* У спота могут быть **ответственные участники** (в доменной модели есть ответственные у `Spot` и у `TaskTemplate`).
* Для некоторых типов спотов предусмотрены **дефолтные шаблоны задач** (рекомендуемый стартовый набор периодических задач). Шаблон включает:
  * название,
  * сложность/очки,
  * расписание,
  * срок выполнения (время до дедлайна после срабатывания расписания).

### ✓ **Задачи**

> В пользовательском интерфейсе Telegram задачи могут отображаться в игровом стиле как **«миссии»**.

* **Разовые** — выполняются один раз до указанной даты (или без даты, если она не задана).
* **Периодические** — имеют шаблон расписания (ежедневно, раз в неделю и т.д.) и создают экземпляры задач по этому расписанию.
  * Для периодических задач существует:
    * **шаблон задачи** (`TaskTemplate`) — общие настройки, расписание, длительность до дедлайна,
    * и **экземпляры задач** (`TaskInstance`) — конкретные дедлайны и статусы.
  * Если наступил следующий срок по расписанию, а активный экземпляр задачи ещё не завершён, **новый экземпляр не создаётся** (ожидаемое поведение совпадает с текущей реализацией: фабрика создания учитывает наличие активного инстанса).
* Все задачи привязаны к конкретному **споту**.
* Участники сами выбирают задачи для выполнения.
* Один экземпляр задачи в каждый момент времени может быть взят в работу только одним участником:
  * есть статусы `Active` / `InProgress` / `Completed`,
  * "взять" задачу переводит её в `InProgress` и фиксирует участника,
  * завершить может только тот, кто её начал.

## **3. Механики мотивации в MVP1**

### 🎮 **1. Очки**

* За каждое выполненное дело участник получает очки, заранее заданные для этой задачи.
* Очки хранятся в контексте семьи.
* Используются для отображения в лидерборде.
* Очки начисляются одинаково для бытовых задач и для задач саморазвития (персональные споты).

### 🎯 **2. Настроение спота**

* У спота есть шкала настроения от «грустного» до «очень счастливого» (0–100%).
* Настроение рассчитывается по задачам спота, **для которых уже наступил срок выполнения** (их `dueAt <= now()`), с
  учётом их важности (очков) и того, **насколько давно прошёл срок выполнения**.
* Задачи могут заранее появляться в списке дел семьи (по расписанию и длительности из шаблона), но **до наступления
  срока (`dueAt`) они не влияют на настроение** — спот не «обижен» за задачи, время которых ещё не пришло.
* Если в текущий момент нет задач, у которых срок выполнения уже наступил (`dueAt <= now()`), — настроение спота
  считается равным 100%.
* Чем дольше важная задача остаётся невыполненной после наступления срока, тем сильнее она «тянет вниз» настроение спота по своим очкам.
* Каждая задача влияет только на настроение того спота, к которому она привязана.
* На текущий момент в коде уже есть формула расчёта (может быть уточнена в ТЗ):
  * учитываются только задачи `dueAt <= now()`;
  * выполненные вовремя дают полный вклад;
  * выполненные с опозданием дают частичный вклад (коэффициент `kLate = 0.5`);
  * просроченные невыполненные задачи дают отрицательный вклад, растущий от 0 до 100% за 7 дней просрочки (`min(1, overdueDays/7)`);
  * итоговая оценка нормируется в диапазон 0–100.
* Важно, что:
  * настроение всегда находится в диапазоне 0–100%,
  * влияние просроченных задач постепенно растёт со временем,
  * после выполнения задачи её негативное влияние полностью прекращается (остаются только положительные эффекты от
    выполненных задач).
* При изменении настроения и пересечении порогов семья получает уведомления (в коде заложены пороги: <20, <50, >=80).

### 🏆 **3. Лидерборд**

* Простой рейтинг по очкам (сортировка по убыванию).
* Очки начисляются каждому участнику отдельно в рамках каждой семьи.
* В одной семье участник видит только свои очки и общий рейтинг по этой семье.
* Лидерборд можно включить или выключить в настройках семьи.
* При выключенном лидерборде:
  * очки по-прежнему начисляются,
  * участники не видят общий рейтинг и сравнение с другими,
  * участник видит только своё количество очков.
* Период рейтинга в MVP1 — за всё время существования семьи (без сезонов и обнулений).

### 🌟 **4. Поощрения и похвала (Future / MVP2+)**

> В будущем планируется добавить механики позитивного подкрепления и привычек в стиле Duolingo.

* **Похвала за выполнение** — короткие сообщения/анимации, которые усиливают ощущение прогресса ("Отлично!", "Ещё один шаг!").
* **Серии (streaks)** — учёт дней подряд с выполненными задачами (на уровне пользователя и/или семьи).
* **Ежедневная цель** — простая цель на день (например, выполнить N задач), с визуальным прогрессом.
* **Награды и бейджи** — достижения за регулярность, вклад в семью, завершение сложных задач, помощь в критические моменты.
* **Уровни/прогресс** — накопительный прогресс (личный и/или семейный), основанный на очках/звёздочках.
* **"Сундуки"/бонусы** — редкие награды за серию/цели (например, декоративные награды, статусы, персональные поздравления).
* **Похвала от семьи** — быстрые реакции/"лайки" и благодарности другим участникам за выполненные задачи.
* **Мягкие напоминания без стыда** — напоминания, которые поддерживают, а не обвиняют.

## **4. Интерфейс Telegram-бота (MVP1)**

### Главное меню:

* 🏠 **Семья** — выбор активной семьи и краткая информация о ней.
* ✅ **Мои задачи** — список доступных/взятых задач (можно взять, выполнить, отказаться).
* 🧩 **Споты** — список спотов ("питомцы/зоны"), их настроение и связанные с ними задачи/шаблоны.
* 📊 **Статистика** — раздел присутствует в меню (детализация может быть расширена).

### Основные сценарии использования:

* Новый пользователь проходит простую регистрацию и при необходимости присоединяется к существующей семье по ссылке.
* Админ семьи управляет составом участников и переключается между несколькими семьями.
* Участник открывает список дел семьи и выбирает, что он готов сделать.
* Пользователь просматривает информацию о спотах и связанных с ними задачах (миссиях).
* Семья смотрит общую статистику и рейтинг, чтобы видеть вклад каждого.
* Пользователь может получить подсказки по возможностям бота и интерфейса.

### Редактирование и управление

* Админ может:
  * создавать семью,
  * создавать приглашения по роли (ссылка вида `https://t.me/<bot>?start=invite_<code>`),
  * управлять участниками (раздел "Управление участниками" доступен из "Семья"),
  * удалять семью.
* Раздел "Настройки семьи" сейчас помечен как "(В разработке)".
* Управление спотами и шаблонами задач реализуется через раздел "Споты" и соответствующие диалоги (conversations).

### Выполнение задачи (миссии):

1. Участник выбирает задачу из списка.
2. Подтверждает выполнение задачи одним действием в интерфейсе.
3. Комментарии/доказательства в текущей реализации не являются обязательной частью флоу.
4. Получает очки, обновляется настроение спота.
5. Всем участникам отправляется уведомление о выполнении.

### Уведомления:

* Уведомления о выполнении задач отправляются всем участникам семьи.
* Сообщения об изменении настроения спота отправляются при значимых изменениях (пересечение порогов).
* Напоминания по задачам предусмотрены на уровне доменных событий (есть событие "reminder due"), но параметры/планировщик и настройки могут уточняться в ТЗ.
